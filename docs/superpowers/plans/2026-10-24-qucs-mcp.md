# Qucs-S MCP — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a Go MCP server for opencode that turns SPICE-like circuit descriptions into validated Qucs-S `.sch` schematics and can run/simulate them via the installed Qucs-S.

**Architecture:** The plan implements the approved design: SPICE-subset parser → model → grid layout + stubs/net labels → `.sch` writer → Qucs-S netlist validation → Qucs-S simulation → dataset parse; MCP tools wrap these stages.

**Tech Stack:** Go 1.27.3, `github.com/modelcontextprotocol/go-sdk` v1.8.0, standard library only, Windows x64, Qucs-S 25.1.1 at `C:\Users\lau\Desktop\Soft\Qucs-S-25.1.1-win64`.

**Spec:** `C:\Users\lau\Desktop\Soft\qucs-mcp\docs\superpowers\specs/2026-10-24-qucs-mcp-design.md`

## Global Constraints

- Go version: 1.27.3 (exact; installed on this machine).
- MCP SDK: `github.com/modelcontextprotocol/go-sdk` v1.8.0 (exact).
- No third-party dependencies besides the MCP SDK; everything else uses the standard library.
- Qucs-S root (default): `C:\Users\lau\Desktop\Soft\Qucs-S-25.1.1-win64`; binary: `bin\qucs-s.exe`; netlist command: `-n --ngspice -i <in.sch> -o <out.cir>`; run command: `-n --ngspice --run -i <in.sch> -o <out.dat>`; dataset header: `<Qucs Dataset 25.1.1>`.
- Platform: Windows x64; server runs over stdio; subprocess invocation via `os/exec` with list args, `cmd.Dir` = schema dir, context timeout.
- Tool naming: snake_case MCP tool names (`create_schematic`, `validate_schematic`, …).
- Values: SPICE `1M` = milli, `1MEG` = mega; Qucs-S uses `1m`/`1M`. Normalization only for bare numeric literals; `{...}` expressions and `.param` values untouched.

## Review Focus

The spec is a vision document and silent on several inputs; the plan must not leave these uncovered:

1. Pin offsets and source polarity for `S4Q_V` (and R/C/L/D/Q/M) — the calibration task must pin these before any layout code depends on them.
2. Value normalization (`M`/`MEG`, expressions) — covered by unit tests in the parser task.
3. Qucs-S version drift — must surface as a clear error, not silent misformat.
4. Simulation returning exit code 0 while the dataset is bad — must check dataset header/vars.
5. MCP transport/config behavior for local stdio registration.
